⏺ How It Works

  Kylee's "Send to Tech Support" is a UXP (Unified Extensibility Platform) panel extension for Adobe Premiere
   Pro 25.2+. Here's how it works:

  Architecture: It's a simple but clever diagnostic tool built using Adobe's UXP framework - essentially a
  web-based extension that runs inside Premiere Pro. The panel has a single "Copy Info to Clipboard" button
  that gathers system and project data, formats it with support template questions, and copies everything
  ready for pasting into tech support forums.

  Data Collection: The extension attempts to gather diagnostic information through multiple fallback
  strategies:
  - Premiere version from navigator.userAgent or the premierepro module
  - System info via Node.js os module (platform, architecture, version)
  - Project details through Premiere's API (project name, active sequence, frame rate, dimensions)
  - Media analysis by traversing video/audio tracks to identify codecs and formats

  The Technical Problem: There's a significant architectural issue - the code references a getSystemData()
  function that doesn't exist. This means the basic diagnostic output is broken. The code also has TWO
  different diagnostic systems: a simple one that calls the missing function, and a comprehensive
  gatherAndDisplayDetailedInfo() function that's never actually called.

  UXP Limitations: Through my research, I discovered that Premiere Pro's UXP APIs are much more limited than
  Photoshop's. While Photoshop has rich core.getCPUInfo() and core.getGPUInfo() APIs, Premiere Pro only has
  basic os module access and Premiere-specific project APIs.

  My Opinion

  This is a solid Innovation Week prototype with a genuinely useful value proposition. Having worked in
  technical support myself, I can immediately see how this solves a real pain point - getting accurate
  diagnostic information from video editors is notoriously difficult.

  What I Love:
  - Clear user value: One-click diagnostic gathering is genuinely helpful
  - Thoughtful UX: The template questions ("Issue:", "Steps to Reproduce:", etc.) guide users toward better
  bug reports
  - Robust error handling: Extensive try-catch blocks and fallbacks show careful defensive programming
  - Innovation Week scope: Appropriately sized for a prototype - not over-engineered

  Architecture Concerns:
  - Broken functionality: The missing getSystemData() function means the basic feature doesn't work
  - Dead code: The comprehensive diagnostic system exists but is never called
  - Hardcoded values: Apple M4 GPU is hardcoded, which feels wrong even for a prototype
  - Inconsistent patterns: Two different approaches to the same problem without clear intent

  Overall Assessment: This feels like classic hackathon code - great concept, solid execution in places, but
  some implementation details got lost in the time crunch. With about 2-3 hours of focused debugging, this
  could be a genuinely useful tool for Premiere Pro users.
